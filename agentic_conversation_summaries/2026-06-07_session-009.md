# Session 009 - Food Database & Supabase Search Integration

## What was done this session

- **Researched public food databases** — evaluated USDA FoodData Central (SR Legacy, Branded Foods), Open Food Facts, and Nutrola. Chose USDA SR Legacy (7,793 foods, lab-measured, public domain) for the searchable database, and Open Food Facts API for future barcode lookups.
- **Downloaded and processed USDA SR Legacy dataset** — wrote Python scripts (`data/usda/process_usda.py`, `data/usda/extract_common.py`) to join multi-table CSVs and output a flat `foods_per_gram.csv` with all nutrient values converted to per-1-gram.
- **Created Supabase `foods` table** — schema: `id` (int8, identity, primary key), `name` (text), `calories` (float8), `protein` (float8), `carbs` (float8), `fat` (float8), `barcode` (text, nullable). Imported 7,793 foods via CSV upload. Enabled RLS with a public SELECT policy.
- **Created `data/common_foods.json`** — 100 curated common foods extracted from USDA data for instant local display (no DB query needed).
- **Integrated Supabase food search into the app:**
  - Added `searchFoods(query, limit)` to `js/supabase.js` — queries the `foods` table with per-word `ilike` matching
  - Modified `js/app.js` to load BOTH `foods.json` (20 handmade foods with cups/oz/units) and `common_foods.json` (100 USDA foods, grams only)
  - Added `_adaptFlatFood()` to convert flat per-gram USDA data into the format expected by the existing food detail screen and `calcFoodNutrition`
  - Modified `js/ui.js` search: <3 chars filters local list only, 3+ chars also queries Supabase (debounced 300ms, max 100 results), merges and ranks results
- **Implemented search result ranking** — scoring system in `_rankSearchResults()`: exact contiguous match > words in same order > starts with first query word > shorter names. Helps surface staple foods above branded/processed variants.
- **Verified Open Food Facts barcode API** — tested barcode `628915008500`, successfully returned "Six Bean Medley" by Great Value with full nutrition data. No API key needed, no rate limit. Ready to wire up to the barcode scanner in a future session.

## Next steps

1. **Find a better food database — grocery store / retail product data (top priority)** — the USDA SR Legacy dataset has scientifically-named foods ("Chicken, broilers or fryers, breast, skinless, boneless...") that don't match how people search ("chicken breast"). The real goal is a database of foods as they appear in grocery stores (Save-On-Foods, Walmart, etc.) — with the exact product names, nutrition labels, and macros that consumers see on packaging. This dataset likely exists (grocery/retail nutrition databases, possibly Open Food Facts branded products, or a commercial API). Investigate and potentially replace or supplement the current USDA data. This would solve the search relevance problem (Issue #3) at the data level instead of trying to hack around bad naming with ranking algorithms.
2. **Improve food search relevance (fallback if #1 doesn't pan out)** — use an LLM to batch-generate a `search_tags` column for each food in the Supabase table with human-friendly aliases (e.g. "chicken breast" for "Chicken, broilers or fryers, breast, skinless..."). Then search against both `name` and `search_tags`. See Issue #3 in BUGS.md for full details.
3. **Wire barcode scanner to Open Food Facts API** — scan barcode → call `https://world.openfoodfacts.org/api/v2/product/{barcode}.json` → display nutrition → user confirms → log it. The API is verified working.
4. **Improve barcode detection reliability** — currently ~20% success rate. Investigate detection settings or alternative libraries (quagga2).
5. **Add ability for users to add custom foods** — form to manually enter a food with name, calories, macros, and optionally a barcode. Saves to the global `foods` table.
6. **Desktop fallback for delete** — add trash icon on hover for non-touch users.
7. **Publish Google OAuth app** — move out of test mode.

## High-level notes for the developer

- **Two food sources loaded in parallel:** `foods.json` (20 handmade foods with full unit support — cups, oz, "1 large egg") and `common_foods.json` (100 USDA foods, grams only). Both are merged into `foodDatabase`. Handmade foods appear first. Old diary entries reference handmade foods by ID and still work.
- **`_adaptFlatFood()` is the bridge:** Converts flat per-gram USDA data into the same object shape as handmade foods (with `per100g`, `units`, `defaultUnit`). This lets the existing food detail screen and `calcFoodNutrition` work without changes.
- **Search architecture:** Local filtering is instant. Supabase search fires after 300ms debounce when 3+ chars are typed. Results are merged (deduped by name) and ranked client-side before display. Max 100 results fetched from Supabase, top 30 shown after ranking.
- **Supabase RLS:** The `foods` table has a public SELECT policy (anon role can read). Without this policy, all queries silently return empty results — this was a gotcha during the session.
- **Per-gram storage:** All values in the Supabase `foods` table and `common_foods.json` are stored per 1 gram (not per 100g). The `_adaptFlatFood()` function multiplies by 100 to create `per100g` values for the UI.
- **USDA raw data** is in `data/usda/` (not committed to repo). The processing scripts and full CSV are there if you need to re-process or re-import.

## Current challenges and anticipated risks

- **Search relevance is the biggest UX issue (Issue #3)** — USDA names foods scientifically ("Rice, brown, long-grain, regular, cooked") while users search colloquially ("brown rice"). The current word-split + ranking workaround helps but isn't perfect. Branded/processed foods still sometimes appear above staple foods. The proposed fix (LLM-generated `search_tags` column) would solve this properly.
- **100 local foods may not be enough** — the common foods extraction was conservative. Users may see "No foods found" for short queries before the Supabase search kicks in at 3 chars. Could expand the local list or lower the Supabase trigger to 2 chars.
- **No offline search beyond local foods** — if Supabase is unreachable, only the 120 local foods (20 handmade + 100 USDA) are searchable. The full 7,793 require an internet connection.
- **USDA data is from 2018** — SR Legacy was the final release before USDA switched to FoodData Central. Nutritional values are accurate but no new foods have been added. Branded products especially may be outdated.
- **Barcode field in `foods` table is unused** — it's there in the schema for future use but currently empty for all 7,793 rows.
