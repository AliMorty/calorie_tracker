# Session 007 - Swipe-to-Delete & Panel Animations

## What was done this session

- **Implemented swipe-to-delete** for food entries in the diary view
  - Swipe left on any food item to reveal a red "Delete" background
  - Swiping past 80px threshold triggers deletion with animation (slide out + collapse)
  - Swiping less than threshold snaps back to original position
  - Direction locking: first 8px of movement determines horizontal vs vertical intent, so scrolling isn't affected
  - Fixed browser back/forward navigation conflict with `touch-action: pan-y`
- **Added slide animations to panels**
  - Add Food panel slides up from bottom (200ms ease-out) and down on dismiss (150ms ease-in)
  - Food Detail screen slides in from right on open, slides down on close/confirm
  - Overlay fades in/out instead of instant toggle
  - Fixed global `.hidden { display: none !important }` overriding transitions by adding specific overrides for animated panels
  - Fixed "spring" artifact on Food Detail exit by disabling transition before swapping CSS classes
- **Made Add Food panel full screen** — changed from 72% height (top: 28%) to full height (top: 0)
- **Removed auto-focus on search input** — keyboard no longer appears immediately when Add Food panel opens; user taps the search box when ready
- **Added UX Polish Roadmap** to `design/UI_SPEC.md` — documented 6 prioritized improvements (optimistic UI, transitions, food DB, incremental DOM, haptics, typography)
- **Attempted and reverted automatic cache-busting** — dynamic timestamp approach worked but user preferred not to use it

## High-level notes for the developer

- **Animation pattern:** Panels use CSS `transform` + `transition` instead of `display: none` toggling. The `.hidden` class still exists globally but animated elements override it with `display: flex/block !important` so transforms can run.
- **Food Detail has asymmetric animation:** enters from right (`translateX(100%)` → `translateX(0)`), exits downward (`translateY(0)` → `translateY(100%)`). This requires a `.hiding-down` class and careful transition disabling to prevent visual jumps between states.
- **No confirmation dialog on delete** — swipe-to-delete is instant (Telegram-style). If accidental deletions become a problem, consider adding an undo toast.
- **Pure CSS + JS implementation** — no external libraries for any animations or gestures.
- **iPhone Safari caching remains unsolved** — no automatic cache-busting is in place. Users on home screen shortcuts must delete and re-add the shortcut to get updates. The timestamp approach was tried and reverted per user preference.

## Current challenges and anticipated risks

- **iPhone caching** — the biggest UX pain point. No good solution for PWA home screen shortcuts on iOS without a service worker cache strategy.
- **No undo mechanism** — accidental swipe-deletes permanently remove the entry.
- **Desktop users can't delete** — no mouse-based delete option yet (only touch/simulated-touch works).
- **Re-render after delete** — full day re-renders after animation. Slow network could cause brief visual glitch.
- **Animation class complexity** — the mix of `.hidden`, `.hiding-down`, `!important` overrides, and transition toggling is getting intricate. If more animated panels are added, consider a unified animation utility.
