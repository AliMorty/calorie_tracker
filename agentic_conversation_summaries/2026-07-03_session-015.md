## High-level notes for the developer

- **The Goals overlay is gone for good.** The app is now genuinely two views toggled by the
  `.hidden` class — no CSS transitions, no slide-in, so none of the session-014 overlay fragility
  applies anymore. Much simpler.
- **Search hits Supabase, not local files.** `js/supabase.js:86` queries the `foods` table.
  `data/common_foods.json` (100 items) is only the offline/browse list. To make ANY new food
  searchable it must be inserted into Supabase — a local-file edit alone won't do it.
- **The `foods` table stores PER-GRAM values.** The app multiplies ×100 (`_adaptFlatFood` in
  `js/app.js`). So the numbers you insert equal the raw `foods_per_gram.csv` row, NOT per-100g.
- **Bottom nav is `position: fixed`** and centered with `max-width: 480px` to match `#app`. If the
  app container width ever changes, update the nav's `max-width` too.
- I did not (and cannot) touch Supabase directly — no credentials in the repo, by design. New
  rows always go via SQL that Ali runs in the dashboard.

## Current challenges and anticipated risks

- **Two-tab layout is untested in a real browser.** It was verified by reading the code only.
  Needs a device test before trusting it. Watch for: `env(safe-area-inset-bottom)` behaviour on
  iPhone, and whether the fixed nav sits correctly above the meals.
- **No `usda_source` / unique-constraint check on the goat-cheese insert.** If the `name` column
  ever gets a unique constraint, a repeat insert would error; would need `ON CONFLICT` upsert.
- Serving sizes remain completely unsolved (USDA is per-100g/per-gram only).
