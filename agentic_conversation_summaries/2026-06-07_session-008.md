## High-level notes for the developer

- **Service worker cache strategy:** Network-first means the app always tries to get fresh files. Cache is only a fallback for offline use. To force all users to get new files, bump `CACHE_VERSION` in `sw.js`. No need for query string cache-busting on CSS/JS references.
- **html5-qrcode manages its own camera:** Unlike Phase 1 where we used raw `getUserMedia`, the library now handles camera access internally. We just provide a container div (`#barcode-reader`) and callbacks.
- **qrbox is the scanning region:** The corner markers drawn by html5-qrcode define the area where barcodes are detected. Removing them (tried during session) caused detection to fail. The barcode must be positioned inside the markers.
- **Camera requires HTTPS:** `getUserMedia` only works on HTTPS or localhost. Desktop localhost works fine; iPhone must access via the GitHub Pages HTTPS URL.
- **Barcode icon uses inline SVG** — no external icon library or image file needed.

## Current challenges and anticipated risks

- **Barcode detection is unreliable (major issue)** — detection works but success rate is roughly 20%. Even barcodes that have been successfully read before require many attempts, repositioning, and patience. Detection got harder after the `aspectRatio: 1.7` parameter was removed from the html5-qrcode config — restoring it may help. Curved/can-shaped barcodes are not detected at all; only flat barcodes on boxes or flat packaging have any chance. This is the top priority to fix in the next session — the feature is not usable in its current state.
- **Camera viewfinder is full screen** — works but isn't the final desired UX. Needs to be resized to a contained area in a future session.
- **iPhone Safari first-load:** The service worker itself needs one fresh load to register. After that, caching is handled automatically.
- **Camera permissions UX:** If a user denies camera access, they need to manually re-enable it in browser settings. The app shows an alert but can't re-trigger the permission prompt.
- **Custom food database not started** — currently no way to store foods with barcodes. This is a prerequisite for making the barcode scanner truly useful beyond what OpenFoodFacts covers.
- **Animation class complexity** continues to grow (noted in session-007).
