## High-level notes for the developer

- **Supabase credentials in code:** The project URL and anon/publishable key are in `js/supabase.js`. The anon key is designed to be public (RLS protects the data), but be aware it's visible in source.
- **Google OAuth credentials:** Client ID and Client Secret are configured in the Supabase dashboard under Authentication → Sign In / Providers → Google. The secret is not in your frontend code.
- **Google OAuth is in test mode:** Only manually added test users (currently `mortyaut@gmail.com`) can sign in. To allow anyone, you need to publish the app in Google Cloud Console → OAuth consent screen.
- **100 user lifetime cap in test mode:** Google allows 100 total users while in test mode, counted over the entire lifetime of the app.
- **Goals are still localStorage-only:** `getGoals()` and `saveGoals()` still use localStorage. If you want goals to sync across devices, you'd need a `user_goals` table in Supabase.
- **storage.js now returns Promises:** All CRUD functions (`getMealsForDate`, `addFoodEntry`, `removeFoodEntry`, `updateFoodEntry`) return Promises. Any code calling these must handle them with `.then()` or `await`.
- **The Supabase free tier pauses after 7 days of no database activity.** Using the app daily prevents this. If paused, data is preserved — just restore from the Supabase dashboard.
- **External service configuration (not in code):**
  - Supabase: Site URL set to GitHub Pages URL, redirect URLs include both localhost:8080 and GitHub Pages
  - Google Cloud: Authorized JS origins include both localhost:8080 and alimorty.github.io
  - Google OAuth consent screen: test user `mortyaut@gmail.com` added

## Current challenges and anticipated risks

- **Google OAuth test mode limitation:** Friends can't sign in until they're added as test users or the app is published. Publishing may require a privacy policy URL and Google review.
- **No data migration path:** Users who had data in localStorage before this change will see an empty diary after signing in. A migration utility (localStorage → Supabase) would be valuable.
- **Supabase CDN dependency:** The app now requires loading `@supabase/supabase-js` from a CDN. If the CDN is down or blocked, the app won't work at all (no graceful fallback to localStorage-only mode).
- **No offline support:** The previous localStorage-only version worked fully offline. Now, if there's no internet, the app shows the login screen. Could add a "use offline" option that bypasses auth.
- **Entry IDs changed format:** localStorage used `Date.now().toString(36) + random`, Supabase uses UUIDs. Any code that assumes a specific ID format could break.
- **Home screen shortcut caching:** Adding the app to phone home screen caches files aggressively. After code updates, users need to delete and re-add the shortcut.
