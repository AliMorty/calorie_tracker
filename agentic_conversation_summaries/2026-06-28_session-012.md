# Session 012 - Form Tagging, Macro Matching Pipeline, Full 913 Run

## What was done this session

### 1. Raw/cooked form tagging (done, reviewed)
- Per Ali's note (`note_to_myself/hand_craft_process.md`): vague names like "lentils" are
  dangerous because raw vs cooked macros differ hugely (lentils raw 352 vs cooked 116 cal/100g).
- **Rule:** tag each item with the form people normally LOG it in — `cooked` for meat/grains/
  legumes/pasta, `raw` for foods eaten raw (most veg, fruit), `none` for items where form is
  meaningless (spices, oils, dairy, condiments, sauces, flour, drinks, nuts, breads).
- Built `data/hand_crafted/tag_form.py`: sends the 913 names to `claude -p` (sonnet) in parallel
  chunks, gets a tag per item (decisions-not-rewrite), Python applies the rename + reconciles
  (913 in = 913 out, nothing dropped).
- **Result:** 240 cooked, 84 raw, 588 none, 1 missed (`salmon, sockeye (fresh)` -> defaulted
  none, should be cooked). 322 items renamed (e.g. `lentils` -> `lentils, cooked`).
- Output: `ingredients_form.json` (913 items, renamed, macros still null), `form_review.txt`,
  `form_tags.json`.

### 2. Macro-matching pipeline (designed, tested heavily)
- **Approach:** for each item, a Python lexical scorer retrieves the top ~12 candidate rows from
  local USDA SR Legacy (`data/usda/foods_per_gram.csv`, 7,794 generic foods, per-GRAM macros ->
  x100 = per-100g). Then `claude -p` (sonnet) picks the best candidate index or -1 (none).
  Runs in parallel chunks, tolerant JSON parsing.
- **Key principle reaffirmed:** the scorer only needs RECALL (get the right row into the ~12);
  the LLM does the smart final pick (handles fat %, raw/cooked, synonyms, "none").
- **Scorer details** (the one in `build_macros.py` / `test_random50.py` is current/good):
  - tokenize (lowercase, strip to a-z0-9% and space, plural-stem). "2%" stays ONE token.
  - +10 per whole-word match (with `wmatch` allowing <=2 char plural diff)
  - +20 if all query words present; +1000 if first segment exactly equals query
  - +8 same head word; +15 prefix; mild +15 cooked/raw form match; -0.2*len(name)
- **BUG we found and FIXED:** an earlier version had special percentage scoring (+60 if any %
  matched). It matched "greek yogurt **5%**" to "Beef, ground, 95% lean / **5%** fat" because the
  beef name literally contains "5%". Fix: REMOVED the % special-casing entirely; "2%"/"5%" are now
  just normal words worth +10. Food words dominate, % is a mild tiebreaker. Re-tested: greek yogurt
  2%->plain lowfat (73), 5%->plain whole milk (97). Correct.
- **Tests run:** 10-item, top-100 (84%), curated-50 with fat variants (96%), tricky-30 (25/30
  after % fix), random-50 from the real list (39/50 = 78%, most misses were exotic items
  genuinely absent from USDA: garam masala, harissa, mirin, curry pastes, etc.).

## THE PROBLEM TO FIX FIRST NEXT SESSION

The 380 "none" rate (42%) is WAY higher than our test rate (~22%). Diagnostic run showed:
**354 of the 380 "none" items DO have USDA candidates available** — only 26 genuinely have zero.
So most "none"s are NOT real no-matches — they are `claude -p` chunks that **silently failed**
(empty/garbled output, almost certainly RATE-LIMITING from running 8 parallel `claude -p`
workers at once). Those items never got a pick and defaulted to none.

Evidence: none list includes obvious foods that should match easily — `baguette`, `almond
extract`, `beef cutlets, cooked`, `beef cheeks, cooked` — these aren't genuine USDA gaps.

### Fix plan (do this first)
1. Re-run matching ONLY for the items currently marked none (or just the 354 that have
   candidates). Do NOT redo the 533 good ones.
2. Reduce parallelism (e.g. max_workers=3-4, not 8) and/or add real per-chunk retry with a
   check that EVERY item in the chunk got a key in the returned dict; retry missing ones.
3. Consider smaller chunks (the build used CHUNK=25; tests that worked used ~17).
4. After re-run, re-check: expect none to drop to roughly ~150-200 (the genuinely-exotic +
   over-specific items: ethnic pastes, exotic cheeses, branded cereals).

## High-level notes / gotchas for the next worker
- **`claude -p` flakiness under high parallelism is the main risk.** 8 concurrent calls caused
  silent empty returns. Keep concurrency low and VERIFY every item got a pick; retry the rest.
  This is almost certainly why 354 good-candidate items came back none.
- **Decisions-not-rewrite is the safety rule throughout** — the LLM returns indices/tags, Python
  applies them and reconciles counts so nothing silently vanishes. Keep doing this.
- **USDA SR Legacy is per-GRAM** in `foods_per_gram.csv` — multiply by 100. Don't forget.
- **Two USDA datasets locally:** `data/usda/` (SR Legacy, generic foods — used for macros) vs
  `data/usda_branded/` (1.8M branded products w/ barcodes — for future barcode scanning, NOT macros).
- **The % special-casing trap:** do NOT re-add percentage-boost scoring. It pulls "5%" foods into
  unrelated "x% fat" rows. Treat % as a plain token. (Documented above.)
- **Original `ingredients_set.json` (1,115 pre-dedup) is untouched and should stay that way.**
- **Ali's preferences (important):** keep answers under ~50 words; do NOT take actions unless
  explicitly asked; explain bash commands term-by-term; he is a vibe coder learning the CLI.
