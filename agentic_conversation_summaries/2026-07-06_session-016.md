### 1. Dark mode (Issue #3) — DONE, deployed
- Refactored `css/styles.css` to route theme-able colors (backgrounds, text, borders) through CSS
  variables (`:root`), and added a `@media (prefers-color-scheme: dark)` block that redefines them.

  literal so they don't invert.
- Commit `9bb98ea`, merged to `main` and pushed → auto-closed #3.

### 2. Edit amount of logged database foods (Issue #5) — DONE, deployed
- Bug: tapping a logged food that came from the USDA/Supabase database did nothing (handcrafted
  foods worked). Cause: `handleEditEntry` looked up the food in `foodDatabase`, which doesn't hold
  database foods, so it silently returned.
- Fix (`js/app.js`): when the lookup misses and the entry was logged in grams, reconstruct a
  gram-based food object from the entry's own stored macros (`per100g = macro * 100 / grams`) and
  reopen the detail screen. Works offline, no lookup needed.
- Documented as Bug #4 in `issue_documentations/BUGS.md`. Commit `72750fb`, pushed → auto-closed #5.

### 3. GitHub CLI (`gh`) set up for the issue-driven workflow
- Installed `gh` and authenticated with a **read-only** fine-grained token, deliberately so the
  agent can **read** issues but **cannot create/close/edit** them. (Issues still auto-close via
  `closes #N` in commits landing on `main` — that's GitHub server-side, not the token.)
- Workflow now: Ali writes needs as GitHub issues → agent reads them with `gh issue list` → fixes →
  references them in commits.

### 4. Barcode scanner rewrite (Issue #4) — PARTIAL, PAUSED
- Replaced the unmaintained `html5-qrcode` (documented to fail on 1D barcodes on newer iPhones) with
  the maintained **`barcode-detector` polyfill** (ZXing-C++ compiled to WASM) via CDN, driving a
  `getUserMedia` `<video>` with a continuous detect loop. Commit `d0cd1a7` (`refs #4`, not closed).
- **Result: works on desktop Chrome (WSL/Windows), but on iPhone Safari the camera does not open.**
  This is an iOS-Safari-specific issue — leading hypothesis: iOS is strict about `video.play()`
  staying tied to the user tap, which `html5-qrcode` used to handle internally. **Paused at Ali's
  request** to prioritise manual food entry; needs the iOS camera fix + on-device retest.

## High-level notes for the developer

- **Everything is deployed via GitHub Pages from `main`.** Pushing to `main` updates the live site
  at `alimorty.github.io/calorie_tracker` in ~1 min. The service worker (`sw.js`) is network-first;
  bump its `CACHE_VERSION` when shipping asset changes so phones fetch fresh (currently `v9`).
- **Feature work is done on branches** (`feature/dark-mode`, `feature/barcode-scanner`) then merged
  to `main`. `main` is the safe restore point.
- **All food macros are per-gram** across the app (Supabase `foods`, `common_foods.json`, manual
  entries should follow suit). The app ×100 to get per-100g. Don't store per-100g.
- **Two food sources with different shapes:** handcrafted foods (`data/foods.json`) have real ids +
  `units`; database foods use `id: name`, grams-only (`_adaptFlatFood`). The #5 fix and the manual-add
  spec both reconstruct gram-based food objects, reusing `showFoodDetail` for rescaling.
- **`gh` is read-only on purpose.** The agent cannot write issues. If Ali wants richer detail on an
  issue (e.g. paste the manual-add requirements into #9), Ali does it on the website.
- Barcode debugging rule (from Bug #1): iOS Safari camera issues must be diagnosed on the actual
  iPhone — don't guess-and-deploy. Establish the exact symptom + screenshot first.
